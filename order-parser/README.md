# order-parser — парсер заказов для фрилансера

Программа раз в несколько минут проверяет биржи фриланса и Telegram-чаты, отбирает заказы
по ключевым словам и присылает подходящие в ваш Telegram-бот:

```
🟠 Разработать Telegram-бота для записи клиентов
💰 до 15 000 ₽ (допустимо до 45 000 ₽)
Kwork · 09.10 14:32

Нужен бот на aiogram: запись на услуги, напоминания, админка…
[ Открыть заказ ]
```

Работает локально на вашем ПК (Windows или Linux), сервер не нужен. Всё в одном процессе:
планировщик опроса сайтов + userbot Telethon для Telegram-чатов + бот aiogram для уведомлений.

| Источник | Как читается | По умолчанию |
|---|---|---|
| 🟢 FL.ru | RSS-лента `fl.ru/rss/all.xml` (+ категории) | включён |
| 🟠 Kwork | JSON биржи `kwork.ru/projects` (запасной путь — `window.stateData` со страницы) | включён |
| 🟣 Habr Freelance | HTML-список задач (RSS — запасной) | **выключен**: сервис закрыт 28.02.2025 |
| 🌐 Freelancer.com | публичный API `/api/projects/0.1/projects/active/` | включён |
| ✈️ Telegram | ваш аккаунт (userbot) слушает новые сообщения в чатах/каналах | включён, если заданы TG_* |

## Быстрый старт

1. Установите **Python 3.11 или новее**.
   - Windows: <https://www.python.org/downloads/>, при установке отметьте **Add python.exe to PATH**.
   - Linux (Debian/Ubuntu): `sudo apt install python3 python3-venv`.
2. Создайте бота: напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
3. Узнайте свой Telegram ID: напишите [@userinfobot](https://t.me/userinfobot). Или впишите в `.env` только
   `BOT_TOKEN`, запустите программу и отправьте своему боту `/start` — пока `ADMIN_ID` не задан, бот отвечает
   на `/start` вашим ID.
4. Для чтения Telegram-чатов получите `API_ID` и `API_HASH` ([инструкция ниже](#получение-api_id-и-api_hash-на-mytelegramorg)).
   Если Telegram-чаты не нужны — пропустите и поставьте `SOURCE_TELEGRAM=false`.
5. Запустите `run.bat` (Windows, двойной клик) или `./run.sh` (Linux). Первый запуск создаст
   виртуальное окружение `.venv`, установит зависимости и создаст файл `.env` из `.env.example`.
6. Заполните `.env`:
   ```ini
   BOT_TOKEN=1234567890:AA...
   ADMIN_ID=123456789
   TG_API_ID=1234567
   TG_API_HASH=0123456789abcdef0123456789abcdef
   TG_PHONE=+79991234567
   ```
7. Откройте своего бота в Telegram и нажмите **Start** — иначе бот не сможет вам писать.
8. Для Telegram-источника перечислите чаты и каналы в `config.yaml` → `telegram.chats`
   (аккаунт должен в них состоять).
9. Снова запустите `run.bat` / `./run.sh`. При первом запуске Telethon попросит в консоли код
   из Telegram (и пароль 2FA, если включён). Сессия сохранится в `data/userbot.session`,
   дальше код не нужен. Войти заранее и проверить, какие чаты находятся: `run.bat --login` / `./run.sh --login`.

Бот пришлёт «✅ Парсер заказов запущен», и дальше будут приходить только **новые** заказы.

## Получение API_ID и API_HASH на my.telegram.org

Нужны, чтобы программа читала чаты и каналы от имени вашего аккаунта (userbot).

1. Откройте <https://my.telegram.org> и войдите по номеру телефона. Код придёт **в приложение
   Telegram** (не по SMS).
2. Выберите **API development tools**.
3. Заполните форму создания приложения:
   - *App title* — любое, например `order parser`;
   - *Short name* — латиницей 5–32 символа, например `orderparser`;
   - *Platform* — `Desktop`; остальное можно не заполнять.
4. Нажмите **Create application** и скопируйте **App api_id** → `TG_API_ID`, **App api_hash** → `TG_API_HASH`.

Важно:
- никому не передавайте `api_hash` и файл `data/userbot.session` — с ними можно управлять аккаунтом;
- оба уже исключены из git (`.env`, `*.session` в `.gitignore`);
- если форма отвечает «ERROR», попробуйте другой браузер, выключите VPN/блокировщики рекламы
  и повторите через некоторое время — это известная особенность сайта.

## Настройка

### `.env` — секреты и флаги

| Параметр | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота от @BotFather | — |
| `ADMIN_ID` | ваш числовой Telegram ID; бот пишет и отвечает только ему | — |
| `TG_API_ID`, `TG_API_HASH` | ключи с my.telegram.org | — |
| `TG_PHONE` | номер аккаунта для userbot, `+7...` | спросит при входе |
| `TG_SESSION` | файл сессии Telethon | `data/userbot` |
| `POLL_INTERVAL` | интервал опроса сайтов, секунды (минимум 30) | `180` |
| `POLL_JITTER` | случайный разброс интервала | `0.2` (±20%) |
| `SOURCE_FL`, `SOURCE_KWORK`, `SOURCE_HABR`, `SOURCE_FREELANCER`, `SOURCE_TELEGRAM` | включить/выключить источник | см. `.env.example` |
| `MIN_BUDGET` | минимальный бюджет в рублях, `0` — без фильтра | `0` |
| `SKIP_NO_BUDGET` | `true` — не присылать заказы без бюджета | `false` |
| `SEND_DELAY` | пауза между сообщениями в Telegram, секунды | `1.5` |
| `HTTP_TIMEOUT`, `HTTP_RETRIES` | таймаут и число повторов запросов к сайтам | `20`, `3` |
| `USER_AGENT` | свой User-Agent (пусто — реалистичный браузерный) | — |
| `SITES_PROXY` | прокси для запросов к сайтам `http://user:pass@host:port`, если Kwork/FL.ru блокируют ваш IP | — |
| `LOG_LEVEL` | `DEBUG` покажет, почему заказ отклонён | `INFO` |

### `config.yaml` — что читать

- `telegram.chats` — чаты и каналы для userbot: `@username`, `https://t.me/...` или id `-100...`.
  Аккаунт должен **состоять** в них: Telegram присылает новые сообщения только из чатов, где вы участник.
- `fl.categories` / `fl.subcategories` — номера категорий FL.ru; пусто — общая лента.
- `kwork.categories` — категории Kwork (`11` — весь раздел «Разработка и IT»).
- `habr.categories` — категории Habr Freelance.
- `freelancer.queries` — поисковые запросы для Freelancer.com.
- `filters.currency_rates` — курсы к рублю для `MIN_BUDGET`.

Номера категорий с названиями перечислены в комментариях в самом `config.yaml`.

### `keywords.yaml` — ключевые слова

```yaml
include:   # заказ подходит, если найдено хотя бы одно
  - telegram бот
  - next.js
exclude:   # стоп-слова: заказ отбрасывается, даже если include совпал
  - курс
```

Файл можно править вручную (подхватывается без перезапуска) или из бота: `/add_kw`, `/del_kw`.

## Запуск

```bash
./run.sh                      # Linux
run.bat                       # Windows
```

Скрипты сами создают `.venv`, ставят/обновляют зависимости из `requirements.txt` и запускают
`python -m order_parser`. Все аргументы передаются дальше, например `run.bat --dry-run --once`.

Параметры:

| Аргумент | Что делает |
|---|---|
| `--dry-run` | печатать подходящие заказы в консоль вместо отправки в Telegram. Бот не нужен, база — в памяти, первый цикл сразу показывает все текущие подходящие заказы |
| `--once` | один цикл опроса сайтов и выход (с итогом по каждому источнику) |
| `--login` | только войти в Telegram-аккаунт (ввести код) и проверить чаты из `config.yaml` |
| `--sources fl,kwork` | запустить только перечисленные источники |
| `--log-level DEBUG` | подробный лог (в том числе причины отклонения заказов) |
| `--env`, `--config`, `--keywords` | другие пути к файлам настроек |

Проверить парсинг без бота и Telegram:

```bash
./run.sh --dry-run --once
```

Логи пишутся в `logs/order_parser.log` (ротация: 5 файлов по 5 МБ), база — `data/orders.db`.

Остановка — `Ctrl+C`. Чтобы запускать автоматически: в Windows — «Планировщик заданий» →
создать задачу «При входе в систему» с действием `run.bat`; в Linux — `systemd --user` или `crontab @reboot`.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/help` | справка и текущий статус |
| `/pause` | приостановить уведомления (заказы продолжают собираться, но не отправляются) |
| `/resume` | возобновить; бот скажет, сколько подходящих заказов было за паузу |

Бот отвечает только `ADMIN_ID`. Пауза сохраняется в базе и переживает перезапуск.

## Как отбираются заказы

1. **Дедупликация.** Каждый заказ запоминается в SQLite (таблица `seen`, уникальная пара
   источник + id) и присылается не больше одного раза.
2. **Первый запуск источника.** Все заказы, которые есть на сайте в момент первого опроса,
   помечаются просмотренными **без отправки** — чтобы не прислать сразу сотню старых. Дальше
   приходят только появившиеся после этого. (Для Telegram это не нужно — слушаются только новые сообщения.)
3. **Стоп-слова** (`exclude`) — если найдено любое, заказ отбрасывается.
4. **Ключевые слова** (`include`) — нужно хотя бы одно совпадение в заголовке или описании.
   Пустой `include` — подходят все заказы.
5. **Бюджет** — если задан `MIN_BUDGET`, заказы с меньшим бюджетом отбрасываются. Валюты
   пересчитываются по `filters.currency_rates`. Заказы без бюджета проходят, если не включён `SKIP_NO_BUDGET`.

Правила сравнения слов:

- регистр не важен, `ё` = `е`, русский и английский;
- слово ищется **с начала слова**: `бот` найдёт «бота», «ботов», «чат-бот», но не «работа»;
  `react` найдёт «ReactJS»;
- у русских слов окончание отбрасывается: `веб-приложение` найдёт «веб-приложения»,
  `вакансия в штат` — «вакансии в штат»;
- между словами фразы допускаются пробел, дефис, `_` или ничего: `mini app` найдёт «Mini-App» и «miniapp»;
- точка в слове необязательна: `next.js` найдёт «NextJS» и «next js»;
- точное совпадение целого слова — в двойных кавычках: в YAML `- '"бот"'` не найдёт «ботинок»;
- стоп-слова (`exclude`) строже: подходят только формы того же слова — `курс` отсечёт «курсы», «курса»,
  но не «курсор» и не «курсив». Учтите, что «бот курса валют» тоже будет отсечён; если такие заказы нужны,
  уберите `курс` из `exclude` или замените на что-то конкретнее, например `онлайн-курс`.

Подсказки:

- на Freelancer.com заказы почти только на английском: добавьте английские слова —
  `/add_kw website, landing page, scraper, scraping, chatbot`;
- русские синонимы, которых нет в списке по умолчанию: `/add_kw парсинг, чат-бот, спарсить`;
- почему заказ не пришёл, видно в логе с `--log-level DEBUG` (строки «отклонён (нет ключевых слов)» и т.п.).

## Источники

Формат каждого сайта проверялся по реальным сохранённым ответам (подробности и происхождение файлов —
в [`tests/fixtures/README.md`](tests/fixtures/README.md)). Все источники реализуют общий интерфейс
`fetch() -> list[Order]`; ошибка одного источника записывается в лог и в `/sources`, остальные
продолжают работать. После ошибки интервал опроса этого источника растёт (×2, ×4, до ×8) и
возвращается к норме после первого успеха.

### 🟢 FL.ru

- Лента `https://www.fl.ru/rss/all.xml` — последние 60 заказов (несколько часов), этого хватает при
  опросе раз в 3 минуты. Категории: `fl.categories` (`?category=N`) и `fl.subcategories` (`?subcategory=N`).
- Бюджет FL.ru пишет в заголовке («Сайт (Бюджет: 15 000 ₽, для всех)») — программа выносит его в поле
  бюджета. Без бюджета — «по договорённости».
- В ленте полный текст есть только у заказов с пометкой «для всех»; у остальных FL.ru обрезает описание
  примерно до 180 символов — полный текст по кнопке «Открыть заказ».
- Ленты категорий — подмножества общей ленты, поэтому по умолчанию читается только общая (1 запрос за цикл).
- Сайт закрыт DDoS-Guard: с домашнего IP работает, с серверов и некоторых VPN бывает `403`. При `403`
  программа один раз заходит на главную за cookies и повторяет запрос.
- В `robots.txt` FL.ru закрывает `/rss/` для поисковых роботов; сама лента — пользовательская
  («Подписаться через RSS»), программа читает её как обычный RSS-клиент: один запрос раз в несколько минут.

### 🟠 Kwork

- Основной способ — тот же запрос, что делает сама страница биржи: `POST https://kwork.ru/projects`
  с `X-Requested-With: XMLHttpRequest`, в ответ JSON с проектами (12 на страницу). Авторизация не нужна.
- Если вместо JSON пришло что-то другое — запасной способ: обычная страница `/projects?c=N`, где те же
  данные лежат в `window.stateData`.
- Категории — `kwork.categories`: `11` — весь раздел «Разработка и IT» одним запросом; подразделы
  перечислены в `config.yaml`.
- Бюджет: «до 1 000 ₽ (допустимо до 3 000 ₽)» — желаемая цена и максимум, который готов заплатить покупатель.
  Для `MIN_BUDGET` сравнивается максимум.
- Сайт закрыт Qrator: при частых запросах отвечает `403 Доступ заблокирован`, иностранные IP часто
  блокируются. Помогает прокси с российским IP: `SITES_PROXY` в `.env`.

### 🟣 Habr Freelance — закрыт

Хабр закрыл сервис **28 февраля 2025 года** (пост «Мы закрываем Хабр Фриланс» в блоге компании).
Модуль `sources/habr.py` всё равно рабочий — на случай, если сайт оживёт:
- проверено: у сайта была RSS-лента `/rss/tasks` (ссылка в `<head>`), но без фильтра по категориям и без
  сохранённых образцов, поэтому основной способ — HTML-список `/tasks?categories=...` (разметка подтверждена
  сохранённой страницей), RSS — запасной;
- при `404/410`, редиректе или странице-заглушке источник пишет понятную ошибку
  «Habr Freelance закрыт 28.02.2025», остальные источники работают.

Включается флагом `SOURCE_HABR=true`.

### 🌐 Freelancer.com

- Публичный API `https://www.freelancer.com/api/projects/0.1/projects/active/` — ключ не нужен.
- По каждому запросу из `freelancer.queries` берутся свежие проекты (`sort_field=submitdate`, полный
  текст и навыки). Поиск API работает «через ИЛИ», поэтому итоговый отбор всё равно по `keywords.yaml`.
- Бюджет показывается в валюте проекта («$30–250 USD», «₹12,500–37,500 INR», почасовые — «… /час»);
  для `MIN_BUDGET` пересчитывается через доллар. **Почасовые ставки с `MIN_BUDGET` не сравниваются.**

### ✈️ Telegram

- Ваш аккаунт (userbot на Telethon) слушает **новые** сообщения в чатах и каналах из `telegram.chats`.
- Заголовок — первая строка сообщения, бюджет ищется по словам «бюджет», «оплата», «цена» или по сумме с валютой.
- Ссылка «Открыть заказ»: для публичных чатов — `t.me/<username>/<id>`, для закрытых супергрупп и
  каналов — `t.me/c/...` (открывается у участников), в обычных группах ссылки нет.
- Аккаунт должен состоять в чате. `run.sh --login` покажет, какие чаты из `config.yaml` найдены.
- Первый вход — интерактивный (код из Telegram), дальше сессия хранится в `data/userbot.session`.
  Если сессия не авторизована, а консоли нет (например, запуск из планировщика), Telegram-источник
  не стартует, остальные работают.

## Проверка и тесты

```bash
.venv/bin/python -m pip install -r requirements-dev.txt     # Windows: .venv\Scripts\python ...
.venv/bin/python -m pytest
```

Тесты не ходят в сеть. Парсеры проверяются на **реальных ответах сайтов**, сохранённых в
`tests/fixtures/` (откуда и когда взят каждый файл — в `tests/fixtures/README.md`).

Сайты со временем меняют вёрстку. Чтобы проверить парсеры на свежих ответах со своего ПК:

```bash
.venv/bin/python -m order_parser.capture          # сохранит ответы в tests/fixtures/live/
.venv/bin/python -m pytest tests/test_live_fixtures.py -v
```

## Решение проблем

| Симптом | Что делать |
|---|---|
| `/sources` показывает `HTTP 403` у FL.ru | сайт за DDoS-Guard, режет «подозрительные» запросы и IP дата-центров. С домашнего IP обычно работает; не ставьте `POLL_INTERVAL` меньше 120; VPN/прокси дата-центра может вызвать блок |
| `HTTP 403` / `429` у Kwork | защита Qrator от частых запросов. Программа сама увеличивает паузу при ошибках; уменьшите число категорий в `config.yaml` |
| «FL.ru вернул не RSS» | вместо ленты пришла страница проверки — подождите, программа повторит позже |
| Бот молчит, в логе «Бот не может написать ADMIN_ID» | откройте бота и нажмите Start; проверьте `ADMIN_ID` (бот подскажет ваш ID на `/start`) |
| «Telegram-сессия не авторизована» | запустите один раз в консоли `run.bat --login` / `./run.sh --login` и введите код |
| Из Telegram-чата ничего не приходит | аккаунт должен состоять в чате; проверьте `run.sh --login` — он покажет, какие чаты найдены |
| Приходит лишнее / не приходит нужное | `--log-level DEBUG` покажет причину отклонения каждого заказа; поправьте `keywords.yaml` |
| `/add_kw` отвечает «keywords.yaml содержит ошибку» | файл правили вручную и допустили ошибку YAML (например, табуляция вместо пробелов). Исправьте файл — бот не перезаписывает его, чтобы не потерять ваши правки |
| Сайты недоступны при запуске без интернета | программа не падает: источники повторяют попытки с растущей паузой, уведомления ждут связи с Telegram |
| После долгого выключения пришли не все заказы | ленты сайтов хранят ограниченное число последних заказов; при перезапуске неотправленные из очереди досылаются |

## Структура проекта

```
order_parser/
  main.py         точка входа, аргументы, запуск всех компонентов
  config.py       настройки из .env (pydantic-settings) и config.yaml
  models.py       модель Order
  db.py           SQLite: seen (дедупликация), состояние источников, статистика
  filters.py      ключевые слова и бюджет
  processor.py    обработка пачки: дедупликация → первый запуск → фильтры → очередь
  notifier.py     формат сообщения, очередь отправки, анти-флуд
  scheduler.py    опрос сайтов с интервалом и jitter, изоляция ошибок
  http.py         HTTP-клиент: User-Agent, таймауты, ретраи с backoff
  capture.py      сохранение живых ответов сайтов для проверки парсеров
  sources/        fl.py, kwork.py, habr.py, freelancer.py, telegram.py (общий интерфейс fetch() -> list[Order])
  bot/handlers.py команды бота
tests/            тесты и фикстуры (tests/fixtures)
keywords.yaml, config.yaml, .env.example, requirements.txt, run.bat, run.sh
```
