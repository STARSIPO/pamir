### 4.2 Модель контента — главный пробел под задачу с 3D

`src/content/types.ts`. Сейчас единственная сущность, близкая к квартирам:

```ts
export interface Floorplan {
  id: string;
  rooms: number;
  area?: number;
  floor?: Localized;
  image?: string;
  available: boolean;      // ← единственный намёк на доступность
```

Чего **нет** и что потребуется для интерактивной визуализации:

- статус богаче булева: `свободна / забронирована / продана`;
- связь юнита с полигоном на плане или с узлом 3D-модели.

## 5. Разбор референса inamstro.md (завершён)

Полные данные: `docs/research/refs-findings.json`. Главное:

### 5.1 Их «интерактивное здание» — это НЕ 3D

Реализовано плагином **Image Map Pro для WordPress**: SVG-полигоны поверх растрового плана этажа,
координаты в процентах от натурального размера картинки, поэтому оверлей масштабируется вместе с растром.

- **покой:** полигоны полностью прозрачны, работает только пульсирующее свечение (1.5s, infinite) как намёк на интерактивность
- **появление:** полигоны «падают» на план при загрузке (`pageload_animation: fall-down`)
- **ховер:** заливка полигона → `rgba(255,255,255,0.4)` за `0.15s cubic-bezier(.55,0,.1,1)` — квартира «загорается» белым на сером плане
- **тултип:** белая карточка, `0.2s`, нулевой радиус, стрелка-указатель. Внутри — количество комнат, площадь и **два изображения рядом: плоский 2D-план + 3D-изометрия той же квартиры**
- **клик:** ничего не происходит

**Чего у них нет** (и где мы можем их обойти): статуса свободна/продана, цены (в разметке есть пустая
строка «Valorea:»), номера этажа, номера блока, ориентации, легенды, диплинка на квартиру. Плюс
карта и сетка карточек-квартир **не связаны** между собой — ховер по плану не подсвечивает карточку.

### 5.2 Мотион у них слабый

Загружено четыре библиотеки анимаций, но живой аудит DOM нашёл **ноль** элементов с классами появления.
Скролл-анимаций практически нет. Липкая шапка просто прибита, без сжатия и смены цвета. Переключение
фильтров, раскрытие «показать ещё» и открытие попапа — мгновенные, без переходов.

**Это возможность:** по анимации обойти референс несложно.

### 5.3 Что у них стоит перенять

- парность шрифтов: контрастная антиква для заголовков + нейтральный гротеск для интерфейса
- нулевой радиус скруглений почти везде — «архитектурная» геометрия
- планировки поданы как **чертежи**: волосяная рамка 1px, без теней и заливок, подписи вынесены за рамку
- крупные цифры как основной приём иерархии (площадь 35px, статистика 90px), подпись демонтирована до 18px
- заголовок + hairline-разделитель, повторённые на каждой секции — дёшево, но создаёт систему
- сдержанная палитра с одним акцентом, который появляется только на CTA
- **пара «2D-план + 3D-изометрия» в тултипе — самая ценная идея на сайте и дешёвая в воспроизведении**
- разные скорости для разных намерений: 0.15s на точном взаимодействии, 0.5s на декоративном ховере
- прогрессивное раскрытие сетки (8 → 8 → 8), а не вываливание всех квартир сразу

## 5А. Разбор референса solomon.md (завершён)

**Главное: solomon.md использует ТУ ЖЕ технику, что inamstro** — Image Map Pro 6.0.18, те же
SVG-полигоны поверх растрового плана. Два независимых сайта-референса пришли к одному решению,
и ни один из них не делает настоящее 3D. Это сильный аргумент за то, чтобы первым этапом делать
SVG-оверлей, а не WebGL.

- **Стек:** WordPress + Elementor 4.2.3 / Pro 4.2.2, тема Hub от LiquidThemes.
  Загружены **GSAP 3.12.5 + ScrollTrigger + SplitText** — но живой аудит показал **ноль инстансов**
  ScrollTrigger и SplitText на странице. Карусели на Flickity. Шрифт Inter, самохостинг.
- **Типографика — слабое место:** одно семейство (Inter), `letter-spacing: normal` везде, никакой
  работы с трекингом. Заглавные как приём для заголовков секций (h2/h3), h1 в обычном регистре.
  Акцент — оранжевый `#FF6600`.
- **Вес:** HTML главной ~543 КБ, высота DOM ~16 800 px. Тяжело.

**Вывод по обоим референсам:** оба выглядят дорого за счёт композиции, типографики и подачи
планировок как чертежей — **не за счёт анимации**. Анимации у них почти нет, а подключённые
библиотеки простаивают. Мы можем обойти оба, просто сделав мотион осмысленно.
